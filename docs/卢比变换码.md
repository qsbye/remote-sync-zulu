# 卢比变换码（Luby Transform Code, LT Code）

> 本文整理自中文维基百科条目「[卢比变换码](https://zh.wikipedia.org/wiki/盧比變換碼)」（CC BY-SA 4.0），已重新排版。

**卢比变换码（LT 码）**是第一个最接近完善的[抹除码](https://zh.wikipedia.org/wiki/抹除码)（erasure correcting code）的实用**涌泉码**（fountain code），由 [Michael Luby](https://en.wikipedia.org/wiki/Michael_Luby) 于 1998 年发明、2002 年发表。

LT 码的两个显著特征：

1. **仅使用异或运算** —— 编码（encode）与解码（decode）都只采用简单且基础的异或（XOR，$\oplus$）。
2. **无码率（rateless）** —— 可以产生无限量的讯息封包，因此接收端只需收到略高于原始数量的封包即可完成解码。

LT 码属于抹除码，适用于在**二进制抹去通道**（binary erasure channel, BEC）上传输。

## 为何要使用 LT 码

### 传统抹去通道：依赖双向沟通

在传统「抹去通道」（erasure channel）上的传输，通常得仰赖发送端与接收端持续性的双向沟通：

1. 发送端（sender）进行编码并传送带有讯息（message）的封包（packet）。
2. 接收端（receiver）在收到每个封包时对其进行评估：
   - 若封包可被解码，则回传确认（acknowledgment）给发送端；
   - 反之，丢弃毁坏的封包，并请求发送端重新发送。
3. 该双向沟通持续进行，直到所有讯息封包都被成功传送且解码为止。

### LT 码：单向广播即可

在现今网络上，许多场景属于[多点传输](https://zh.wikipedia.org/wiki/多點傳輸)（multicast），发送端不可能与所有接收端逐一确认封包传递与否。为维持传输的正确性，必须使用涌泉码——特别是 LT 码——这类方式传输：

1. 发送端同样进行编码并传送带有讯息的封包。
2. 接收端对每个收到的封包进行评估：出现错误则丢弃，正确则收纳为讯息的一部分。
3. 当接收端收齐足以完整解码的有效讯息时，才发送一次确认给发送端，停止传送。

### 两种方式对比

| | 传统抹去通道传输 | LT 码（涌泉码）传输 |
|---|---|---|
| 确认机制 | 每个封包逐一确认（ACK/NACK） | 收齐后仅确认一次 |
| 毁坏封包 | 请求重传 | 直接丢弃，等待后续封包 |
| 适用场景 | 单播、点对点 | 多点传输（multicast）、广播 |
| 解码条件 | 所有封包成功送达 | 收到「足够多」编码封包即可 |

## LT 编码（Encoding）

将待传送的讯息分割成等长度的 $n$ 个封包（packet），然后不断重复以下步骤产生编码封包：

1. **产生度数（degree）** —— 透过随机数产生器（random number generator）依特定的[几率分布](https://zh.wikipedia.org/wiki/機率分佈)（probability distribution）产生一个整数度数 $d$，且 $1 \ll d \ll n$，代表一个编码封包需要包含的原始封包数量。
2. **均匀选取封包** —— 在 $n$ 组封包中，以[离散型均匀分布](https://zh.wikipedia.org/wiki/離散型均勻分佈)（uniform distribution）选取 $d$ 组封包。
3. **异或运算** —— 将 $d$ 组封包做异或（XOR）运算，要传送的封包即为：

$$M_1 \oplus M_2 \oplus \dots \oplus M_d$$

   其中 $M_1, M_2, \dots, M_d$ 是从总共 $n$ 组封包中挑选出来的 $d$ 组。
4. **附加头部讯息** —— 封包前面附加额外讯息，包括整份讯息有多少个封包（$n$ 个）、是哪 $d$ 个封包被做了 XOR 运算。
5. **附加侦错码** —— 封包末尾附加某种形式的侦错码（可能是[循环冗余校验](https://zh.wikipedia.org/wiki/循環冗餘校驗)（cyclic redundancy check, CRC）），之后才进行传输。

以上步骤不断重复，直到接收端判断讯息已被完整接收并成功解码。

## LT 解码（Decoding）

解码过程同样使用「异或」（XOR，$\oplus$）还原被编码的讯息：

1. **丢弃无效封包** —— 若封包格式错误（侦错码校验失败），或该封包是已处理过封包的复制品，则丢弃。
2. **逐步消去度数** —— 其余封包进入解码程序；其工作原理是利用 $A \oplus A = 0$ 的特性，逐步消去每个封包的度数（degree），直到获得总共 $n$ 个度数为 1 的不同封包为止。范例如下：

$$
\begin{aligned}
&(M_1 \oplus \dots \oplus M_d) \oplus (M_1 \oplus \dots \oplus M_{k-1} \oplus M_{k+1} \oplus \dots \oplus M_d) \\
&= M_1 \oplus M_1 \oplus \dots \oplus M_{k-1} \oplus M_{k-1} \oplus M_k \oplus M_{k+1} \oplus M_{k+1} \oplus \dots \oplus M_d \oplus M_d \\
&= 0 \oplus \dots \oplus 0 \oplus M_k \oplus 0 \oplus \dots \oplus 0 \\
&= M_k
\end{aligned}
$$

即：将一个包含 $M_k$ 的高度数封包，与另一个除 $M_k$ 外成分完全相同的封包做异或，即可单独还原出 $M_k$。每还原出一个原始封包，又能代入其余封包继续消元，如同涟漪般逐步解开全部讯息。
